数据集选择：互补融合

从“单数据集不满足三任务”出发，组合课程数据与 GenImage 做互补。

结论：课程数据更适合解释/定位，GenImage 提供真假分类信号，混合后才能支撑统一三任务训练。

初始问题

  • 课程参考集缺少完整分类训练信息
  • 单一来源难同时覆盖分类、解释、定位

最终选择

  • 分类：引入 GenImage 数据
  • 解释/定位：使用课程相关数据
  • 训练目标：统一模型三头联合输出
Acc / AP BLEU / ROUGE-L IoU / PixF1

训练架构：混合数据的统一多任务框架

单张图进入共享骨干网络，同时产出分类 logits、解释特征、定位 mask logits。

结论：通过 partial labels（has_cls / has_exp / has_loc）实现“不同来源样本按任务可用标签参与训练”。

训练策略：先热身再联合

每次关键改动后先跑 smoke 验证链路，再进入正式训练与验收评估。

结论：两阶段策略降低了改动风险，问题可以在小成本阶段提前暴露并修复。

Stage A（分类热身）

  • 先稳定真假分类能力
  • 快速验证数据读入与损失收敛

Stage B（联合训练）

  • 分类 + 解释 + 定位联合优化
  • 在 partial labels 约束下共享骨干

验证闭环

  • smoke：看链路是否打通
  • formal：看课程验收指标
  • 单图推理：看可视化结果是否合理

问题修复：定位全 0 的根因与闭环验证

通过数据与阈值链路排查，定位到 mask 生成值错误导致监督被清空。

结论：`polygon_to_mask` 前景值由 1 改 255 后，定位训练与评估恢复非零，单图推理 mask 不再纯黑。

问题原因

  • `polygon_to_mask()` 前景值被写成 1
  • `ToTensor()` 后变成 1/255
  • 再经 `> 0.5` 阈值后被全部清空
  • 训练和评估都等价于全零 mask 监督

修复方式与结果

  • 将前景值从 1 改为 255
  • 修复后 smoke：IoU 0.1048，PixP 0.3013，PixR 0.1662，PixF1 0.2142
  • 单图推理：预测 mask 不再为纯黑图

诊断分类偏低：关键是生成器域偏移

第一次正式测试后分类偏低，进一步做课程 fake 来源统计与训练集来源对照。

结论：主问题不是阈值，而是训练 fake 生成器覆盖不足，必须补充多源生成器数据。

课程 fake 来源（多生成器）

adm、biggan、glide/vqdm(1000)、midjourney、sdv4、sdv5、wukong。

多域分布 难度差异显著

线上模型辅助增强：方案设计

围绕“本地稳定主干 + 远程能力补强”，设计 4 个方案并实际尝试前 3 个。

结论：方案设计完整，但线上链路受稳定性与一致性约束，必须做策略化接入而非全量替换。

方案概览

  • A 解释增强：本地判别与定位不变，远程只增强 explanation
  • B 难例复判：本地先判，边界样本路由远程复判
  • C 离线蒸馏：采集 teacher 输出蒸馏回本地模型
  • D 长期方向：持续蒸馏与策略迭代闭环

架构参考图

方案 A：解释增强（200 样本）

本地模型继续负责分类与定位，远程多模态模型仅生成更自然、更细致解释文本。

结论：自动指标未优于本地基线，ROUGE-L 接近平局但 BLEU 明显落后，整体效果并不好。

方案 B：本地先判 + 难例路由远程复判

完成 Plan B 接线后做全量评测，并输出 policy 可观测统计。

结论：这版策略导致分类下降，且 override 比例高、一致率低；fallback 暴露线上稳定性瓶颈，效果不好。

方案 C：离线蒸馏（按 prompt 主口径）

跑通基于 `qwen3-vl-plus` 的 teacher 采集与蒸馏训练，得到 `outputs_llm_distill/best.pt`。

结论：本版蒸馏呈现“分类/解释下降、定位上升”的分化，不是整体提升。
