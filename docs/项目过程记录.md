#### 当前理解
- 这个项目不只是判断图片真假，还要求说明伪造原因，并指出伪造区域
- 解释任务中的伪造痕迹大致可分为：
  - Physics：光照、反射、透视、物理规律违背
  - Distortion：颜色纹理失真、噪声模糊、材质表达错误、风格异常
  - Structure：物体变形、不对称、文字结构异常等
- 当前判断是：SynthScars 主要提供伪造痕迹相关标注，更适合用于解释与定位任务，不太适合作为“真假分类”任务的完整训练依据
- 当前数据集选择上，不使用 Holmes
- 真假分类任务将额外引入 GenImage 数据集，并先采用其中一部分数据开展训练与验证
- 当前多任务框架已经可以完成基础训练、开发评估、课程验收评估和单图推理流程
- 课程验收数据集不是统一多任务同图评估集，而是分类、解释、定位三个独立子集，因此最终验收应当是同一个模型分别在三部分数据上评估后汇总指标
- 先前定位指标全 0 的主因已经确认并修复，当前旧的正式训练 checkpoint 不再可信，因为它是在错误定位监督下训练出来的
- 当前分类任务的另一个关键问题也已经明确：课程 fake 数据生成器种类比原始 ADM 训练集丰富得多，因此后续分类训练必须继续扩充多生成器数据来源，不能只依赖单一 ADM
- 新的正式训练模型已经在课程数据集上验证出更好的分类与定位表现，但生成器拆分后可以看到，模型的泛化仍主要集中在 `adm` 与 `biggan`，对 `glide/vqdm1000`、`midjourney`、`wukong` 等未覆盖生成器仍然明显不足
- 当前 explanation 模块本质上仍是检索式 baseline，优点是稳定、实现轻，缺点是语言表达天花板明显，因此非常适合后续接入线上多模态大模型做 explanation 增强、难例复判和离线蒸馏

#### 下一步
- 优先补充 `glide/vqdm1000`、`midjourney`、`wukong`、`sdv5` 等 fake 数据源，继续提升分类对未见生成器的泛化能力
- 如果新增生成器数据源后继续训练，优先考虑按生成器做更均衡的 fake 采样，而不只是简单的总池随机截样
- 继续优化定位头结构、损失权重与训练轮数，观察课程定位指标是否还能进一步提升
- 如果需要增强展示效果或 explanation 质量，优先尝试“本地模型输出 + 线上多模态大模型 explanation 增强”的轻量接线方案

#### 当前理解
- 线上多模态大模型作为 explanation 增强模块的第一版接线已经可用，并且不会破坏本地分类与定位主流程
- explanation 任务当前出现了一个很明确的现象：自动指标不仅受“有没有说对图”影响，还强烈受“输出是否贴近课程标注模板”影响
- 当前本地 explanation baseline 的问题不只是语言表达不自然，更关键的是经常检索到和当前图像无关的说明；这会导致人工观感很差，但因为句式接近课程参考模板，自动指标未必立刻拉开
- 远程 explanation 在保持贴图性的同时，只要把输出语言和模板风格收敛到课程标注格式，BLEU / ROUGE-L 就可以明显逼近本地 baseline
- 在课程 explanation 全量 200 张样本上，当前远程版本已经在 ROUGE-L 上与本地 baseline 基本打平，但 BLEU 仍明显落后，说明其内容主干与参考标注已较接近，但措辞和模板风格还不够像课程标准答案
- 从样本级统计看，remote ROUGE-L 优于 local 的样本已超过一半（52.5%），但 remote BLEU 仅在 11.5% 样本上更好；这进一步说明当前主要短板不是“看不懂图”，而是“输出风格尚未充分对齐课程标注模板”
- 因此后续如果要继续提升 explanation 结果，重点不应只放在“模型更强”，而应同时优化：图像贴合度、输出模板风格、以及与课程标注格式的一致性
- Plan B 当前这版在课程验收集上并未带来整体收益：相对本地基线（Acc≈0.699、AP≈0.833），分类出现明显下降（Acc≈0.604、AP≈0.794）；解释 BLEU 下降而 ROUGE-L 基本持平；定位基本不变（符合 Plan B 不改定位分支的预期）
- 从 policy 可见，当前策略的主要问题不是“没触发远程”，而是“触发后大比例 override 且远程与本地一致率偏低”：classification 中 override 占 routed 的约 79%，但 remote_agreement_rate 仅约 19%，导致远程复判对分类稳定性造成明显扰动
- routing reasons 以 `fake_low_mask_support` 为主，说明基于掩码不一致的 hard-case 规则当前阈值偏激进，触发了大量低质量复判路径
- 当前可观测性增强后，已经能直接定位性能下降来源：路由率、覆盖率、一致率、fallback 原因都可量化，不再是“黑盒变差”

#### 下一步
- 先做 Plan B 保守化调参并复测：提高 `remote_override_confidence_min`（如 0.85~0.9），收紧 `score_margin`，并下调 `fake_low_mask_support` 的触发敏感度，目标优先恢复分类 Acc/AP
- 固定同一 checkpoint 做 `mode=local` 与 `mode=plan_b` 的多次 A/B 复跑，结合 policy 统计观察“路由率-一致率-收益”关系
- 针对 fallback 两类主因（超时、JSON 解析失败）优化远程调用稳健性与输出 JSON 约束，降低无效路由成本
- 若保守化后仍无收益，短期将 Plan B 定位为人工复核辅助链路，默认评测继续使用 local 模式
- 后续训练/评测/推理命令统一使用 GPU 路径，不再采用 CPU 回退
