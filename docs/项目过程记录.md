# 项目过程记录

## 项目概述
- 项目：AI 伪造图像检测与解释
- 核心目标：
  1. 伪造检测 / 分类

#### 当前理解
- 这个项目不只是判断图片真假，还要求说明伪造原因，并指出伪造区域
- 解释任务中的伪造痕迹大致可分为：
  - Physics：光照、反射、透视、物理规律违背
  - Distortion：颜色纹理失真、噪声模糊、材质表达错误、风格异常
  - Structure：物体变形、不对称、文字结构异常等
- 当前判断是：SynthScars 主要提供伪造痕迹相关标注，更适合用于解释与定位任务，不太适合作为“真假分类”任务的完整训练依据
- 当前数据集选择上，不使用 Holmes
- 真假分类任务将额外引入 GenImage 数据集，并先采用其中一部分数据开展训练与验证
- 当前多任务框架已经可以完成基础训练、开发评估、课程验收评估和单图推理流程
- 课程验收数据集不是统一多任务同图评估集，而是分类、解释、定位三个独立子集，因此最终验收应当是同一个模型分别在三部分数据上评估后汇总指标
- 先前定位指标全 0 的主因已经确认并修复，当前旧的正式训练 checkpoint 不再可信，因为它是在错误定位监督下训练出来的
- 当前分类任务的另一个关键问题也已经明确：课程 fake 数据生成器种类比原始 ADM 训练集丰富得多，因此后续分类训练必须继续扩充多生成器数据来源，不能只依赖单一 ADM
- 新的正式训练模型已经在课程数据集上验证出更好的分类与定位表现，但生成器拆分后可以看到，模型的泛化仍主要集中在 `adm` 与 `biggan`，对 `glide/vqdm1000`、`midjourney`、`wukong` 等未覆盖生成器仍然明显不足
- 当前 explanation 模块本质上仍是检索式 baseline，优点是稳定、实现轻，缺点是语言表达天花板明显，因此非常适合后续接入线上多模态大模型做 explanation 增强、难例复判和离线蒸馏

#### 下一步
- 优先补充 `glide/vqdm1000`、`midjourney`、`wukong`、`sdv5` 等 fake 数据源，继续提升分类对未见生成器的泛化能力
- 如果新增生成器数据源后继续训练，优先考虑按生成器做更均衡的 fake 采样，而不只是简单的总池随机截样
- 继续优化定位头结构、损失权重与训练轮数，观察课程定位指标是否还能进一步提升
- 如果需要增强展示效果或 explanation 质量，优先尝试“本地模型输出 + 线上多模态大模型 explanation 增强”的轻量接线方案
- 如有需要，可继续把 `docs/训练推理架构图.html` 扩展成更完整的项目说明页，用于汇报、答辩或系统设计展示
