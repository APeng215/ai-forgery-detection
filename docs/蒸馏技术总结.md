## 2. 设计背景与目标

项目是统一多任务模型（分类 + 解释 + 定位），且训练数据存在部分标注（partial labels）。

在这种条件下，蒸馏的目标不是替代原监督，而是增强模型在以下方面的学习稳定性：

1. 分类分支：用软标签提供更平滑的类别信息。
2. 解释分支：用特征级对齐提升解释表征一致性。
3. 多任务协同：在 Stage B 联合训练中帮助模型更稳定地收敛。

当前实现遵循“低侵入、可回退”原则：

1. distill 默认关闭。
2. 关闭后行为与原训练流程一致。
3. 仅在配置开启时注入蒸馏项。

## 3. 模块结构

蒸馏相关模块位于 [distill](distill) 目录：

1. [distill/interface.py](distill/interface.py)
- DistillProvider：离线教师缓存模式的蒸馏入口。
- init_ema_teacher：在线 EMA 教师初始化。
- update_ema_teacher：EMA 参数更新。
- compute_online_distill_loss：在线教师蒸馏损失计算。

2. [distill/losses.py](distill/losses.py)
- classification_kd_loss：分类 KL 蒸馏损失。
- explanation_feature_kd_loss：解释特征蒸馏损失（cosine 或 mse）。

3. [distill/cache.py](distill/cache.py)
- OfflineTeacherCache：加载并查询离线教师缓存。

4. [distill/build_cache.py](distill/build_cache.py)
- 从教师 checkpoint 批量生成离线缓存。

5. [distill/compare_checkpoints.py](distill/compare_checkpoints.py)
- baseline 与蒸馏 checkpoint 指标对比工具。

## 4. 三类蒸馏路径

### 4.1 offline_cache（离线教师缓存）

核心思路：

1. 先准备教师模型 checkpoint。
2. 用 [distill/build_cache.py](distill/build_cache.py) 对 Stage B 训练集离线前向。
3. 生成以 image_path 为键的缓存文件。
4. 训练时 DistillProvider 按 batch 的 image_path 回查教师输出。

优点：

1. 训练时不需要教师前向，开销小。
2. 可复用同一缓存做多组学生实验。

局限：

1. 依赖现成教师模型。
2. 依赖 image_path 对齐，路径不一致会导致覆盖率下降。

### 4.2 ema_online（无教师在线蒸馏）

核心思路：

1. 用当前学生模型拷贝初始化 EMA teacher。
2. 每个训练 step 后，用指数滑动平均更新 teacher 参数。
3. Stage B 时 teacher 与 student 对同一 batch 同步前向。
4. 用 teacher 输出作为软监督蒸馏 student。

优点：

1. 不需要额外下载教师模型。
2. 不需要准备缓存文件。
3. 非常适合当前“先落地再迭代”的阶段。

局限：

1. 训练时需要额外 teacher 前向，计算开销更高。
2. 若训练轮次太短，teacher 可能不够强，收益不稳定。

### 4.3 方案三（线上大模型教师 -> 离线缓存蒸馏）

核心思路：

1. 用 [distill/collect_llm_teacher.py](distill/collect_llm_teacher.py) 调用 OpenAI-compatible 接口，采集教师 JSONL。
2. 用 [distill/build_cache_from_llm.py](distill/build_cache_from_llm.py) 将 JSONL 转为 `teacher_cache.pt`。
3. 用 `offline_cache` 模式训练学生模型。
4. 用 [distill/compare_checkpoints.py](distill/compare_checkpoints.py) 对比 baseline 与蒸馏模型指标。

工程化入口：

1. [distill/run_llm_distill_pipeline.py](distill/run_llm_distill_pipeline.py) 一键串联采集、转缓存、训练、对比。

优点：

1. 不依赖本地强教师 checkpoint。
2. 线上教师可快速迭代提示词与模型版本。
3. 仍可复用离线缓存训练路径，训练阶段稳定。

局限：

1. 采集阶段依赖网络与 API 配额。
2. 教师输出质量受提示词和模型稳定性影响。
3. 需额外控制采样规模与重试策略，避免时间成本过高。

## 5. 当前蒸馏目标与损失

当前实现只蒸馏两个分支：

1. 分类分支
2. 解释特征分支

定位分支当前未蒸馏。

### 5.1 分类蒸馏

函数：classification_kd_loss

做法：

1. 对 student logits 与 teacher logits 做温度缩放。
2. 对应分布计算 KL 散度。
3. 乘以温度平方进行标准缩放补偿。

### 5.2 解释特征蒸馏

函数：explanation_feature_kd_loss

可选模式：

1. cosine：最常用，关注方向一致性。
2. mse：关注向量值一致性。

默认是 cosine。

### 5.3 蒸馏总损失组合

总蒸馏损失由三层权重构成：

1. cls_weight：分类蒸馏子损失权重
2. exp_weight：解释蒸馏子损失权重
3. total_weight：蒸馏总项对总训练损失的权重

训练总损失为：

任务监督损失 + 蒸馏损失

## 6. 与原训练流程的融合方式

入口见 [train_multitask.py](train_multitask.py)。

### 6.1 数据层变更

collate_fn 增加了 image_path 字段，用于：

1. offline_cache 模式按路径查教师输出。
2. 蒸馏覆盖率统计。

### 6.2 损失层变更

compute_batch_loss 在原 cls/loc/exp 监督损失后追加蒸馏项：

1. offline_cache 模式：调用 DistillProvider.compute。
2. ema_online 模式：调用 compute_online_distill_loss。

### 6.3 阶段控制

通过 stage_b_only 控制蒸馏阶段：

1. true：仅 Stage B 启用（当前推荐）。
2. false：Stage A 与 Stage B 都启用。

### 6.4 日志与可观测性

run_epoch 会聚合并打印 epoch 级 distill 统计，包括：

1. distill_cls_loss
2. distill_exp_loss
3. distill_loss
4. distill_coverage（离线缓存模式）

- 解释蒸馏子项权重。

10. exp_mode
- cosine 或 mse。

- 仅 offline_cache 生效，缺失缓存是否报错。

## 8. 配套工具与工作流

详细流程图见：[蒸馏全流程图.md](蒸馏全流程图.md)

### 8.1 离线缓存构建

脚本：[distill/build_cache.py](distill/build_cache.py)

作用：

1. 加载教师 checkpoint。
2. 构建 Stage B 训练集。
3. 批量前向输出 logits 与 explanation_features。
4. 存盘为 samples 字典。

### 8.2 结果对比

脚本：[distill/compare_checkpoints.py](distill/compare_checkpoints.py)

作用：

1. 读取两个 checkpoint 的 metrics。
2. 按指标输出 baseline、candidate、delta。

默认比较指标：

Acc, AP, BLEU, ROUGE-L, IoU, PixP, PixR, PixF1, loss

### 8.3 方案三一键流水线

脚本：[distill/run_llm_distill_pipeline.py](distill/run_llm_distill_pipeline.py)

作用：

1. 采集线上教师输出（支持 `--limit`、`--resume`、重试与退避）。
2. 构建离线教师缓存。
3. 启动蒸馏训练。
4. 可选自动执行 checkpoint 对比。

常用控制参数：

1. `--limit`：教师采集上限。
2. `--max-retries`、`--retry-initial-delay`、`--retry-backoff`、`--retry-max-delay`：网络重试策略。
3. `--resume`：断点续采。
4. `--skip-collect`、`--skip-train`：分阶段执行。

## 9. 近期实验观察（smoke 规模）

### 9.1 方案三 smoke（limit=80）

baseline: `outputs_smoke_baseline_fast/best.pt`  
candidate: `outputs_llm_distill_smoke/best.pt`

对比结果：

1. Acc：持平（0.666667 -> 0.666667）
2. AP：下降（0.755073 -> 0.661490）
3. BLEU：提升（0.352172 -> 0.380501）
4. ROUGE-L：小幅下降（0.299567 -> 0.294388）
5. IoU/PixP/PixR/PixF1：均为 0（smoke 下不具代表性）
6. loss：上升（1.355101 -> 1.421842，越低越好）

### 9.2 解读

1. 小样本方案三在解释文本上有一定增益（BLEU）。
2. 分类 AP 与整体 loss 暂未受益，说明教师信号与监督目标仍需进一步对齐。
3. smoke 结果波动较大，应通过更高 `--limit` 和更长训练再判断最终趋势。

## 10. 风险与建议

1. 离线缓存模式最稳定，适合先把训练链路跑通。
2. EMA 模式实现简单，但更依赖训练轮次和算力。
3. 线上大模型教师路径最灵活，但需要控制成本、重试、输出格式稳定性。
4. 建议优先顺序：EMA / offline_cache 基础链路稳定 -> 小规模 LLM teacher 采样 -> 正式规模对比实验。
