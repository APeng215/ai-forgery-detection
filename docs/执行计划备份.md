# Execution Plan

## Context
当前仓库只有数据与文档，没有现成训练代码。最终目标不是分别交付三个独立系统，而是实现**一个统一多任务框架**：对同一张输入图像，同时输出三项结果：
- 任务 1：真假分类
- 任务 2：伪造解释
- 任务 3：痕迹定位

同时，最后必须能够稳定汇报课程要求的全部指标：
- **任务 1**：Acc、AP
- **任务 2**：BLEU、ROUGE-L
- **任务 3**：IoU、PixP、PixR、PixF1

数据使用边界已经明确：
- `data/2026-课设数据集/`：**只用于最终课程验收，不参与训练**
- `data/imagenet_ai_0508_adm/`：用于真假分类训练
- `data/SynthScars/`：用于伪造解释与痕迹定位训练，并在联合阶段补充 fake 类监督

## Recommended approach
### 1. 统一模型，而不是三个独立模型
采用一个共享视觉主干 + 三个任务头的结构：
- **共享骨干**：ResNet50
- **分类头**：输出 real / fake 概率
- **定位头**：输出伪造区域二值 mask
- **解释头**：输出解释文本

最终推理接口必须是**单图统一输出**：
- classification score / label
- explanation text
- localization mask

### 2. 训练策略：效果优先，选择“先热身再联合”
a.k.a. **单模型两段训练**，不是三个独立模型。

推荐原因：
1. `imagenet_ai_0508_adm` 规模远大于 `SynthScars`，如果从零开始完全混合训练，分类梯度很容易压过解释和定位任务。
2. `imagenet_ai_0508_adm` 只有分类标注，`SynthScars` 主要提供解释和定位标注，监督不完整，直接从零统一混训更不稳定。
3. 先把共享骨干训出稳定的真假判别能力，再联合优化解释和定位，通常更容易拿到更好的最终指标。

因此，虽然最终是**一个统一模型**，训练上推荐如下：

#### 阶段 A：分类热身
- 数据：`data/imagenet_ai_0508_adm/train/{ai,nature}`、`.../val/{ai,nature}`
- 目标：先训练共享骨干 + 分类头
- 首轮规模：每类先采样 1 万张
- 输出重点：先稳定拿到 **Acc、AP** baseline

#### 阶段 B：联合训练
- 数据：混合使用 `data/imagenet_ai_0508_adm` 与 `SynthScars`
- 方式：单训练入口 + mixed dataloader + loss masking
  - **Imagenet AI batch**：只计算分类损失 `L_cls`
  - **SynthScars batch**：计算 `L_cls + L_loc + L_exp`
- 其中：
  - `L_cls`：真假分类损失
  - `L_loc`：mask 定位损失
  - `L_exp`：解释生成/匹配损失
- 总损失：`L = w_cls * L_cls + w_loc * L_loc + w_exp * L_exp`

#### 阶段 C：联合微调与验收导向调参
- 在验证集上联合观察三组指标：
  - 分类：**Acc、AP**
  - 解释：**BLEU、ROUGE-L**
  - 定位：**IoU、PixP、PixR、PixF1**
- 调整 loss 权重、采样比例、学习率
- 目标不是单项最优，而是**三项任务整体可交付**

## Dataset alignment strategy
### 1. `data/imagenet_ai_0508_adm/`
当前已确认：
- `train/ai`：162000 张
- `train/nature`：157453 张
- `val/ai`：6000 张
- `val/nature`：6000 张

用途：
- 主要用于真假分类监督
- 在统一框架中负责训练共享骨干的基础判别能力

首版策略：
- 第一轮每类先采样 1 万张
- 输入分辨率先用 `224 x 224`
- 优先把 **Acc、AP** 跑通

### 2. `data/SynthScars/`
当前已确认：
- `train/images`：11182 张
- `train/annotations/train.json`
- `test/images`：1000 张
- `test/annotations/test.json`

标注结构：
- `caption`：整图解释
- `refs[].sentence + refs[].explanation`：局部解释
- `refs[].segmentation`：定位多边形

用途：
- 主要用于解释与定位监督
- 在联合阶段，这些样本同时可作为 fake 类样本补充分类监督

验证策略：
- 从 `train` 中切分 10% 作为验证集
- `test` 保留为最终评估

### 3. `data/2026-课设数据集/`
用途：
- 只用于最终课程验收
- 不参与训练

验收目标：
- 任务一：输出分类并统计 **Acc、AP**
- 任务二：输出解释并统计 **BLEU、ROUGE-L**
- 任务三：输出 mask 并统计 **IoU、PixP、PixR、PixF1**

## Model design
### Shared backbone
- 第一版固定使用 **ResNet50**
- 原因：稳定、成熟、易复现，适合作为 5070 Ti 上的 baseline 起点

### Classification head
- 输入：共享骨干特征
- 输出：二分类 logits
- 评估接口必须直接输出：
  - **Acc**
  - **AP**

### Localization head
- 输入：共享骨干中高层特征
- 输出：单通道二值 mask
- 首版仅做“伪造区域 / 背景”的二分类分割
- `segmentation` 多边形统一转为 mask，多 refs 合并为同一前景 mask
- 评估接口必须直接输出：
  - **IoU**
  - **PixP**
  - **PixR**
  - **PixF1**

### Explanation head
- 输入：共享骨干视觉特征，可选融合定位区域特征
- 第一版采用**检索/模板式解释头**，而不是重型生成模型
- 这样仍属于统一框架，因为解释头直接消费同一个共享骨干特征
- 后续若效果不足，再升级为轻量生成式解释头（LoRA 优先）
- 评估接口必须直接输出：
  - **BLEU**
  - **ROUGE-L**

- `src/preprocess/synthscars_masks.py` — 将 SynthScars 的 `segmentation` 转为 mask
- `src/models/backbone.py` — ResNet50 共享骨干

- `src/models/heads/localization_head.py` — 定位头
- `src/models/heads/explanation_head.py` — 检索/模板式解释头
- `src/models/multitask_model.py` — 统一多任务模型
- `src/training/losses.py` — 多任务损失与权重

- `evaluate_multitask.py` — 统一评估脚本，汇总课程要求全部指标
- `infer_multitask.py` — 单图统一推理
- `configs/multitask.yaml` — 统一训练配置

## Verification

- 抽样读取 Imagenet AI ADM，确认 real/fake 标签映射正确
- 抽样读取 SynthScars，确认 `caption`、`refs`、`segmentation -> mask` 转换正确

### 2. 模型验证
- 单 batch 前向传播时，统一模型能同时跑通：
  - classification head
  - localization head
  - explanation head

### 3. 训练阶段验证
- 阶段 A：输出 **Acc、AP**
- 阶段 B/C：同时输出
  - **Acc、AP**
  - **BLEU、ROUGE-L**
  - **IoU、PixP、PixR、PixF1**

### 4. 统一推理验证
- 对单张图片，一次推理返回：
  - 分类结果
  - 解释文本
  - 定位 mask

### 5. 最终验收验证
- 对课程验收数据跑统一评估流程
- 最终至少整理出：
  - 一张三任务指标汇总表
  - 若干分类案例
  - 若干解释案例
  - 若干定位可视化案例

## Resource strategy for 5070 Ti
- 单卡训练
- 开启混合精度
- 分类输入先用 `224 x 224`
- 定位输入先用 `256 x 256` 或 `384 x 384`
- 解释头首版用检索/模板式，避免一开始就引入高成本生成模型
- 优先保证**课程要求指标完整可交付**，再考虑更复杂方案

## Final recommendation
如果目标是“最终效果更稳、课程指标更容易全部交出来”，推荐采用：
- **一个统一多任务模型**
- **ResNet50 共享骨干**
- **先热身再联合** 的训练方式
- **首版解释头用检索/模板式**

这不是拆成三个系统，而是在**一个模型**上用更稳的训练路径，去最大化最终的 Acc、AP、BLEU、ROUGE-L、IoU、PixP、PixR、PixF1。
