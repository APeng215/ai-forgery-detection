1. 训练策略

smoke 的时序

现在 prompt 里已经改成：smoke 是正式训练前的低成本链路验证， 用来确认分类、解释、定位三条链路都能正常训练与评估。

正确时序是 smoke → Stage A → Stage B， 而不是把 smoke 理解成插在 A 和 B 之间的中间步骤。

2. A / B 分阶段训练

当前代码的真实行为

根据 train_multitask.py 与 README.md：

  • Stage A：只用分类数据做真假分类热身。
  • Stage B：使用 joint_train = ConcatDataset([stage_a_train, synth_train])。
  • 这意味着 Stage B 里分类监督仍然存在，同时叠加解释与定位监督。

所以“Stage B 只训练解释和定位、不再训练分类”这句话，按当前代码来说是不对的。

3. 全 0 问题修复

为什么 1/255 会出错

你的直觉是对的：1/255 ≈ 0.0039，确实小于 0.5。

  • 背景原本是 0。
  • 错误前景被画成 1。
  • ToTensor() 会把 8-bit 灰度缩放到 [0,1]。
  • 所以背景变成 0.0，前景变成 1/255。
  • 后面再做 (mask_tensor > 0.5).float() 时，前景和背景都会变成 0。

修成 255 后，前景才会变成 1.0，阈值化结果才正常。

5. 方案 B

什么是 remote_agreement_rate

这里更准确地说，是“远程一致率”，不是“和真值的一致率”。

在 src/inference/plan_b.py 里，它的定义是： remote_agreement_rate = remote_agreement_cases / remote_response_cases。

  • 分子：远程返回结果后，与本地判断一致的样本数。
  • 分母：远程真正返回了结果的样本数。

所以它衡量的是“本地与远程两套判断之间是否稳定一致”，而不是整体准确率。

7. 方案 C

什么叫“分类监督塌缩”和“伪 logits”

“分类监督塌缩”可以通俗理解为：监督信号变得太单薄， 最后几乎只剩“这张偏 fake / 这张偏 real”的硬标签味道， 原本更丰富的类别边界和不确定性信息被压扁了。

“伪 logits”则是指：这些 logits 不是 teacher 分类头直接前向算出来的， 而是后处理“凑”出来的。

在 distill/build_cache_from_llm.py 里，流程是：

  • 先从 LLM 输出拿 final_label + confidence 或 fake_score。
  • 把它转成 p_fake。
  • 再通过 log([1-p, p]) 构造两维 logits。

因此它不是 teacher 模型原生分类头输出，而是由标签和置信度映射出来的“伪 logits”。

8. 方案 C 再核对

“更偏向定位分支”是否成立

我查了 distill/interface.py，当前蒸馏只作用在两部分：

  • classification logits
  • explanation_features

代码里并没有单独的 localization distill loss， 所以“蒸馏仅在 Stage B 生效，更偏向定位分支”这句没有直接代码依据。

更准确的说法只能是：蒸馏发生在 Stage B，可能通过共享 backbone 间接影响定位， 但目前没有硬证据能直接证明它“偏向定位分支”。
